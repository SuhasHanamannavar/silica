1. Specifications (Design Specification)

Input: Product requirements, system requirements, and chip architecture requirements.

Output:

1. Functional specification document
2. Microarchitecture specification document
3. Design requirements document
4. Interface specifications (inputs, outputs, protocols, and bus interfaces)
5. Clock and reset requirements
6. Performance, power, and area (PPA) targets
7. Memory and register specifications
8. Instruction set or feature specifications, if applicable
9. Verification plan and test scenarios
10. Design constraints and technology requirements

2. RTL Design (Register Transfer Level Design)

Input: Functional specification, microarchitecture specification, and interface specifications.

Output:

1. RTL source code (Verilog, SystemVerilog, or VHDL)
2. RTL module hierarchy
3. RTL design files
4. Finite State Machine (FSM) implementation
5. Register and datapath implementation
6. Interface logic implementation
7. Clock and reset logic
8. Parameter and macro definitions
9. RTL design documentation
10. Initial lint and code-quality reports

3. Functional Verification

Input: RTL source code, functional specification, microarchitecture specification, and verification plan.

Output:

1. Verification environment and testbench
2. Directed test cases
3. Constrained-random test cases
4. SystemVerilog Assertions (SVA)
5. Functional coverage reports
6. Code coverage reports
7. Simulation logs and waveforms
8. RTL bug reports
9. Regression test reports
10. Verification sign-off report
11. Formal verification results, if formal methods are used
12. Verified RTL release candidate

4. Logic Synthesis

Input: Verified RTL source code, technology library files, timing constraints (SDC), and synthesis constraints.

Output:

1. Gate-level netlist
2. Technology-mapped netlist
3. Standard-cell utilization report
4. Timing analysis report
5. Area report
6. Power estimation report
7. Synthesis warnings and error reports
8. Design rule and constraint violation reports
9. Unmapped or unsupported logic reports, if any
10. Synthesis optimization reports
11. Updated timing and area statistics
12. Netlist for physical design

Overall Flow:

Specifications → RTL Design → Functional Verification → Logic Synthesis → Gate-Level Verification → Design for Test (DFT) → Floorplanning → Placement → Clock Tree Synthesis (CTS) → Routing → Physical Verification → Static Timing Analysis (STA) → Sign-off → Tape-out → Fabrication → Packaging and Testing.

Important Notes:

- Specifications define what the chip must do.
- RTL design describes how the chip's digital logic behaves.
- Functional verification checks whether the RTL meets the specifications.
- Logic synthesis converts RTL into a gate-level netlist using a target technology library.
- Functional verification and RTL design usually proceed iteratively, with bugs identified during verification being fixed in the RTL.
- Synthesis does not normally wait for all verification to finish; preliminary synthesis can run in parallel with verification.
- The output of synthesis becomes an important input to physical design.
- Additional checks, such as equivalence checking, confirm that synthesis preserves the intended RTL behavior.
- The exact deliverables depend on the chip type, design methodology, EDA tools, and project requirements.
